# design-sprites

A design sprite is a standalone web app (Next.js + TypeScript) that hosts one design Project: an append-only verbatim record, a chat + question-card UI, and a deterministic state machine with an MCP server — and **no built-in AI**. The interviewer is an external agent (Muse or Claude Code) driving the sprite over MCP: predicting every answer, asking only where its guess is weak, judging each prediction hit or miss, and re-deriving a living decision model (`model.md`) from the verbatim record. When the deterministic sharpness gate passes, the driver declares the model sharp; the human presses Commit, and the deliverable (model, record, transcript) freezes as an exportable bundle.

v3.5 adds a `preview` question type (2–4 sandboxed, script-free HTML-snippet variants plus slider dials, driven through the same MCP turn protocol) and makes dark/light always follow the OS/browser `prefers-color-scheme` — theme tokens only, no toggle or setting. v3.6 adds a batch-answering flow (Next open question + "N of M answered" header progress; the pane never auto-closes or auto-advances on save), a jump-to-question navigator (Questions section, status only), a sticky chat composer docked to the chat column, mobile round 2 (sticky Save bar in the answer pane, dial touch targets at least 44px), and an optional driver-side ds-wake bridge (`template/tools/ds-wake/`) that wakes a Claude Code driver session via Channels, with `wait_for_input` as the fallback. v3.7 adds a driver-presence banner (runtime heartbeat from MCP activity / the ds-wake bridge, read on the UI's 4s poll; honest "a driver is attached — it will be woken by your activity" semantics), keeps answered questions fully editable in the answer pane, trims the sidebar to files + export only, gives question cards a status-coloured outline (blue = open, green = answered; the status word stays), and restyles the thread as a chat — messages as sender-labelled bubbles, questions as generative-UI-style widget cards with the recommendation inside the card. v4 adds the design surface: driver-authored standalone HTML artifacts (versioned on every write, script-free page gate, stable element ids enforced) shown as widget cards in the thread and opened in a full-canvas layout mode with a version switcher; the Agentation inspector annotator in layout mode (element notes land in the record with their element identity; the driver reads, replies, and resolves them over MCP); and two locked working rules — design starts with structure (layout and hierarchy in grayscale) before colour, and annotation is always Agentation. Agentation is PolyForm Shield 1.0.0 (© 2026 Benji Taylor), integrated via its npm packages; the licence and notices ship in `template/THIRD-PARTY-NOTICES.md`.

**The skill is [SKILL.md](SKILL.md)** — read it, or hand it to any coding agent: `Read vicyap/design-sprites/SKILL.md`.

Layout:

- `SKILL.md` — the canonical skill (v4; copy-paste ready).
- `brief.md` — the founding brief (v1, 2026-11-11), kept verbatim for the record; where it describes rounds, submit, or email, SKILL.md (v4) supersedes it.
- `template/` — the v4 sprite app template (Next.js 15 + React 19 + TypeScript; Drizzle + SQLite on the sprite disk; MCP over Streamable HTTP; app `design_sprite`, version 4.0.0-p5), including its `DEPLOY.md` runbook, the optional `tools/ds-wake/` Channels bridge, and `THIRD-PARTY-NOTICES.md` (Agentation's PolyForm Shield licence). Sprites need **no `conn:*` labels** — the app makes no AI calls. v4 sprites run a second service on the sprite: `agentation-mcp` on loopback 4747 for the annotator (see `template/DEPLOY.md`).
- `.claude/skills/design-sprites/SKILL.md` — a symlink to the root `SKILL.md`, so Claude Code sessions mounting this repo discover the skill automatically. One canonical file; the link never drifts.
